1. Teacher mode

Open the app with index.html?teacher=1. It starts in teacher mode. In teacher mode, question blocks are ordinary blocks: whatever you put in a question's slot stays there as its reference answer. Nothing vanishes. Keyboard navigation is on when the page opens; the Navigation button left of the badge turns it off and on.

  1. The Teacher badge. It changes to Learner when teacher mode is off.
  2. The Settings gear.
  3. Teacher mode switch. Turn it off to try the task exactly as a learner would; turn it on again to keep editing.
  4. The Hint category holds the question blocks. Learners never see it.
  5. Opens this Teacher guide.

2. Add a question

  1. Open the Hint category.
  2. A value question fits where a value goes, such as the right side of set number to or the condition of an if.
  3. A statement question fits in a stack of steps. It can ask for one block or a sequence.

Drag a question into the program, or insert it with the keyboard (E, T, then Enter on the question). The Edit question form opens as soon as it is placed.

3. Edit a question

Open the form any time: press Enter on a question (or click it), then choose Edit question. Save applies all changes as one step you can undo.

  1. What goes in the question block: a value, one statement, or a sequence (with a minimum number of blocks).
  2. What the learner hears: an optional needs phrase, the short prompt, and a longer instruction.
  3. Category of the intended block.
  4. Block: pick it by its picture; screen readers hear its name.
  5. Add it to the intended blocks.
  6. The intended blocks. Any block that fits the shape can be placed, but only these count as a fitting answer.
  1. The hidden reference answer (see section 4).
  2. Put in slot to edit moves it back into the question's slot when you save.
  3. Remove deletes it when you save.
  1. Written hints, read one at a time after the learner's first try, in this order.
  2. AI help allowed: off, or up to Nudge (a guiding question), Point (names the idea or category) or Show the kind (names the block). Also set how many AI hints, and an optional note for the AI.
  3. Offer choices: learners may pick from a few real blocks made from the reference answer. Never offered in quizzes.
  4. Save.

4. Reference answers

In teacher mode, build the correct answer inside the question's slot. That is the question's reference answer. Export task XML hides it inside the question and empties the slot, so learners start with an empty question and never see it. Choices and scaffolds use it.

  1. A value question holding its reference answer, number + 4.
  2. A statement question holding its reference answer, print number.

5. Make a scaffold

A scaffold turns the program on the workspace into a partial program: the parts that carry the lesson's key concept become questions. Open Settings → Make scaffold….

  1. Key concept: questions go where it appears. Let the AI decide picks one for you.
  2. Learner level: beginners get fewer, smaller questions; advanced learners get more, including loops, ifs and runs of steps.
  3. How many questions this gives, from how many possible places.
  4. Make scaffold.
  1. The new question, holding the removed part as its reference answer. Each question comes with a prompt, an instruction, two written hints, AI hints and choices. Review it with Edit question, or undo the whole scaffold with one Ctrl+Z.

Without the AI, the rules still choose the places and the questions get simple text you can edit.

6. Tasks, tests and assessment

  1. Activity: Practice, or Quiz. In a quiz only the questions can be changed, learners are not told whether an answer fits, and choices and AI hints are off.
  2. Export task XML: the task as learners first see it, with reference answers hidden.
  3. Import task XML: opens a task, or a learner's saved work.
  4. Make scaffold… (section 5).
  5. Task tests…: checks of the whole program that only teachers see.
  1. Inputs: answers typed into prompt blocks, one per line, in order.
  2. Expected output: lines that must be printed, in this order. Other printed lines are allowed.
  3. Add test for another case.
  4. Run tests saves the tests and assesses the program on the workspace.

Assess a learner's work

The learner uses Settings → Save my work and sends you the file. Open it with Import task XML and press Run.

  1. After the program's own output, the Assessment starts.
  2. Every question in program order: where it is, its prompt, and whether it is empty, fits, or doesn't fit (with what the learner used).
  3. Every task test: pass, or fail with the reason. Tests are skipped while a question is empty.

Learners never see tests or assessments: their Run only notes how many questions are still unanswered.
